# 日镜账

中文名：**日镜账** · 前缀 `daysnap` · 端口 **6600 / 11600**

## 骨架

**日终余额抽取 → 周期快照落行 → 变动流水回放核对 → 断档/跳变检出 → 快照与回放差额清单**

皮：收单/结算账户的日终余额镜。去皮是 **周期快照事实 + 流水回放守恒 + 断档跳变检出**，不是银行核心 CRUD、不是日结封账锁定、不是双边齐账。

```bash
docker compose up -d --build
```

## 主链对象

| 对象 | 作用 |
| --- | --- |
| 账户册 | 参与日终抽取的账户 |
| 变动流水 | 按营业日增减额 |
| 周期快照 | 账户×营业日余额镜 |
| 回放核对 | 前日快照+当日流水 vs 当日快照 |
| 差额清单 | 不一致行 |
| 断档/跳变 | 缺前日镜、偏离阈值 |
| 旁置簿 | 未入账载荷 |
| 父镜固化 | 父户日终镜 = 子户当日有效镜汇总（乙·指纹固化） |
| 子齐集闸 | 父键×营业日的应收/实收/缺子核证与正式写闸 |
| 旁置父镜 | 齐集未满时的非权威父值现场，补齐后须显式晋升 |

## 子齐集闸 · 乙案：旁置后显式晋升

本题择定 **乙案 `B_SIDELINE_THEN_PROMOTE`**：父抽开始即持久化齐集行，齐集号固定为
`齐集-{父键}-{营业日}`（例：`齐集-户汇总-2026-12-11`），并贯穿子快照、父镜、周期快照、回放与差额行。

- 应收子集合来自父子配置，停用子户不会被静默吞掉；实收按当日有效子快照核库。
- 缺一子时：**不写状态为 `有效` 的正式父镜**，只写 `旁置父镜` 与缺子清单；抽取接口仍返回 `409`，不得报父抽成功。
- 补齐子户后普通重抽只把旁置刷新为 `齐集已满·待晋升`，仍不写正式镜；必须调用显式晋升。
- 晋升会重新核库、固化指纹父镜、关闭活跃旁置，并把同一齐集行置为 `正式有效/valid=true`。
- 回放拒绝旁置父权威；相关差额行带同一齐集号和“拒父权威”原因。
- SQLite `BEGIN IMMEDIATE` + 锁内重核保证子抽/父抽竞争时不会留下“父正式已成而子缺”的现场。

| 入口 | 作用 |
| --- | --- |
| `GET /api/核证/子齐集?齐集号=` | 真实只读核证：齐集号、应收/实收、缺子列表、旁置有无、父正式有无、valid |
| `GET /api/核证/子齐集?键=齐集号或父键` | 基线兼容入口；同一齐集号可打开同一现场 |
| `GET /api/齐集` / `GET /api/父旁置?仅活跃=true` | 齐集行列表 / 旁置父镜列表 |
| `POST /api/齐集/晋升` | 显式晋升；body 可传 `齐集号` 或 `父键/账户键 + 营业日` |
| `POST /api/齐集/标记父成功` | 失败闭试金石：齐集未满时即使带 `父成功:true` 也返回 409 |
| `POST /api/父镜/抽取` | 单父户抽取，同样过齐集写闸 |
| `POST /api/齐集/演练` | 执行缺子、补齐、显式晋升端到端夹具 |

兼容别名包括 `/api/齐集/核证`、`/api/子齐集/核证`、`/api/quorum/cert`、
`/api/核证/子齐集/{齐集号}`、`/api/父旁置/晋升`，以及 `quorum_no/missing_children/has_sideline/official_exists` 等英文字段。

前端入口：台面提示条 → `/子齐集?齐集号=...`；齐集页和父镜页通过 URL 中的同一 `齐集号` 打开相同缺子/旁置现场。

夹具：`fixtures/子齐集缺子样例.json`、`fixtures/子齐集晋升样例.json`、`fixtures/子齐集并发样例.json`，
并提供 `父子*`、`齐集*` 命名别名。回归测试 `backend/tests/test_子齐集闸.py` 显式断言正式父镜数量/有无与缺子清单。

## 子户汇总镜 · 乙·指纹固化

父户无直接流水：父户日终有效镜**只**来自子户当日有效镜汇总，父余额与每个子快照指纹在抽取时一并固化。
父对外主读只读固化行（`父镜` / `周期快照` 的父行），**读时绝不 JOIN 子表**。

| 入口 | 作用 |
| --- | --- |
| `GET /api/父镜` | 父镜固化行列表（对外主读） |
| `GET /api/父镜/行?账户键=&营业日=` | 单行主读，只读固化表 |
| `POST /api/父镜/核证` | 只读：固化余额/指纹 vs 现场重算，报 `指纹匹配`/`valid`/`失配子` |
| `POST /api/父镜/重汇总` | 显式重汇总，重新固化指纹（唯一会刷新父值的路径） |
| `POST /api/父镜/配置` / `解绑` | 父子配置（仅单层），配置即旁置父键直接流水 |
| `POST /api/父镜/演练` | 跑 `fixtures/父子汇总样例.json` / `篡改子镜样例.json` / `父子并发样例.json` |

口径要点：

- **子户不齐父镜不得假成功**：齐集行在父抽开始时落库，正式父镜写前在 `BEGIN IMMEDIATE` 事务内重核应收/实收。乙案会提交子快照、齐集行和非权威旁置现场供核证，但正式有效父镜为 0，接口返回 409 并列出缺子；补齐后须显式晋升。
- **与子抽并发同批可见**：父镜批次必等于其子快照批次。
- **父键直接流水旁置**：装载/配置/抽取三条路径都旁置，不参与汇总与回放。
- **篡改可区分**：只改库篡改子快照后，父对外主读不变（乙），核证报指纹失配；`显式重汇总` 才刷新。回放对父户只做指纹核对，不读父键流水。
